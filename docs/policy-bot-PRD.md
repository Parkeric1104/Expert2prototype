## 1. 배경 / 문제

세법/노무 AI 도우미의 기획 정책(답변 유형, 멀티턴 횟수, 의견서 플로우, 피드백 게이팅 등)이
PRD·코드 주석·커밋 메시지·ECM(OneFFICE) 문서에 흩어져 있다. 팀원(PM·디자이너·개발자)이
"이 정책이 뭐였지?"를 확인하려면 사람에게 묻거나 코드를 뒤져야 한다.

→ **정책을 한 곳에 모으고, 질문하면 근거 문서와 함께 답해주는 내부 챗봇**을 만든다.

## 2. 목표 / 비목표

### 목표 (POC)
- G1. 팀원이 자연어로 기획 정책을 질문하면 **근거 문서 발췌 + 출처**로 답한다.
- G2. 정책 문서를 **로컬 DB에서 관리**한다 (커밋/재배포 없이 추가·수정).
- G3. 어떤 질문이 들어오는지 **대화 로그를 축적**한다 (문서화 우선순위 파악용).
- G4. 프로토타입 본체와 **주소·코드 경로를 분리**해 운영한다.

### 비목표 (POC에서 하지 않음)
- 정식 배포·인증(사내 SSO)·권한 관리
- 관리용 UI (문서 편집 화면) — *"UI는 나중에"* 확정
- ECM 자동 동기화 (인증 제약, §7)
- 답변 품질 고도화(임베딩 검색, 평가 루프)

## 3. 사용자 / 시나리오

- **사용자**: 세법/노무 도우미 팀 내부 구성원 (PM·디자이너·개발자). 엔드유저 아님.
- **S1**: 디자이너가 "플로팅 버튼 라벨 분기 기준?"을 질문 → 확정일·PRD ID 포함 답변.
- **S2**: 신규 합류자가 온보딩 중 정책을 챗봇으로 self-serve 학습.
- **S3**: PM이 대화 로그를 보고 "자주 묻는데 문서가 없는 정책"을 발견 → 문서 보강.

## 5. 데이터

로컬 SQLite (`server/policy-db.mjs`). 정식 전환 시 스키마 그대로 Postgres(Neon/Supabase) 이관.

```sql
policies  (id TEXT PK, title, source, content, updated_at)   -- 정책 문서 (md)
chat_logs (id PK, question, answer, sources JSON, offline, created_at)
```

- 시드: 최초 실행 시 `docs/policies/*.md` + ONBOARDING/Guidelines/DESIGN_SYSTEM 자동 적재.
- `data/`는 gitignore — POC 동안 데이터는 각자 로컬 보관.

## 6. 아키텍처

### 현재 (POC)
```
브라우저(/policy-bot.html)
  → GET /api/policy-bot/policies  (Vite 개발서버 미들웨어)
  → SQLite data/policy-bot.db
답변: 클라이언트 키워드 검색(발췌 제시) · 로그: POST /api/policy-bot/logs
```
- `npm run dev` 하나로 전부 동작. 프로덕션 정적 배포본은 번들 문서 폴백(PB-007).

### 정식 전환 경로 (참고)
```
저장소: Neon/Supabase(Postgres)  ·  API: Vercel proxy/  ·  LLM: Claude (proxy/api/policy-bot.js)
검색: pgvector 임베딩(문서 증가 시)  ·  진입: 위젯(PB-008) or 독립 도메인
```

## 7. 제약 / 리스크

| 항목 | 내용 | 대응 |
|---|---|---|
| ECM 인증 | 공유 토큰 링크가 그룹웨어 로그인으로 리다이렉트 (2026-07-27 확인) | 수동 내보내기 → `docs/policies/` 커밋 or DB API 등록. API 확보 시 PB-012 |

| 데이터 휘발 | 로컬 DB는 개인 머신에만 존재 | POC 한정 수용. 공유 필요해지면 §6 정식 전환 |
