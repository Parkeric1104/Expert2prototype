# 기획 정책 지식 베이스 (Policy KB)

내부 팀원용 **기획 정책 챗봇**(`?view=policy-bot`)이 참조하는 문서 폴더.

## 지식 소스

**범위: 기획 정책 문서만** (PRD Q1 결정 2026-07-27 — 디자인 가이드/온보딩 문서는 제외).

챗봇 지식 베이스는 두 층으로 동작한다 (`src/app/data/policy-kb.ts`):

| 층 | 소스 | 반영 방법 |
|---|---|---|
| 로컬 DB (POC, 우선) | `data/policy-bot.db`의 `policies` 테이블 | `POST /api/policy-bot/policies`로 등록, 또는 이 폴더 md 추가 후 최초 시드 |
| 번들 폴백 | 이 폴더의 `*.md` (README 제외) | 커밋 → 빌드 시 포함 (DB 없는 배포본용) |

문서는 `## 제목` 단위로 분할(청크)되어 검색되므로, **주제별로 `##` 섹션을 나눠 작성**할 것.

## ⚠️ 내부 ECM(OneFFICE) 자동 동기화 — 현재 불가

정책 원본은 내부 그룹웨어 ECM(`gwa.douzone.com/ecm/oneffice`)에서 관리 중이나,
공유 토큰 링크가 **그룹웨어 로그인(인증 팝업)으로 리다이렉트**되어 익명 접근이 불가하다
(2026-07-27 확인). 따라서 현재는 자동 동기화가 불가능하고, 아래 중 하나가 필요하다:

1. **수동 내보내기(현재 방식)**: ECM에서 문서를 md/텍스트로 내보내 이 폴더에 커밋
2. **ECM API 확보 시**: 서비스 계정/API 토큰이 확보되면 `scripts/sync-policies.mjs`
   형태의 동기화 스크립트를 추가해 CI에서 주기 동기화 가능 (문서 목록 API + 본문 API 필요)

## 문서 작성 규칙

- 파일명: `kebab-case.md` (예: `multi-turn-policy.md`)
- 첫 줄 `# 제목` = 문서 제목 (챗봇 출처 표기에 사용)
- 정책 확정일/출처가 있으면 섹션에 명시 (예: "정책 확정 2026-07-03")
